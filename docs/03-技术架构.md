# 03 技术架构

## 1. 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Go 1.26（本机已装 1.26.1） | Viva 要求 Go ≥ 1.26 |
| UI 框架 | `github.com/vivaui/viva v0.2.1` | 指定框架；GPU 原生、无 WebView，启动快、包小 |
| macOS 原生调用 | cgo + Objective-C（`.m` 文件，`-fobjc-arc`） | 与 Viva 自己的 darwin 后端一致；需 Xcode Command Line Tools（本机已装） |
| Windows 原生调用 | 纯 Go：`syscall` / `golang.org/x/sys/windows` | 与 Viva 的 Windows 后端一致，无 cgo，可在 macOS 上 `GOOS=windows` 交叉编译 |
| 图像处理 | 标准库 `image`、`image/png`、`image/draw` | 不额外引依赖 |
| 标注栅格化 | 自己实现抗锯齿描边（见 05 文档 §4） | 简单图元，几百行代码，免依赖 |

依赖原则（来自 Viva 指南）：发布二进制里新增任何第三方依赖前，先测量 strip 后体积、启动时间、空闲内存。允许的例外：`golang.org/x/sys`。

## 2. Viva 能力盘点

已核对 Viva `v0.2.1` 源码，下表是本项目会用到的能力，和**需要我们自己补的缺口**。

| 需求 | Viva 提供 | 结论 |
| --- | --- | --- |
| 托盘图标 + 原生菜单 | `Application.AddStatusItem(StatusItemConfig{Icon, Tooltip, Menu, OnClick})`，`MenuItem{Title, Checked, Disabled, Separator, Submenu, OnSelect}` | 直接用 |
| 多窗口 | `app.RunApplication(start)`、`Application.OpenWindow(Config, *ui.Canvas)`、`Window.Show/Hide/Close/Frame` | 直接用 |

| 剪切板图片 | 只有**读**：`app.HasClipboardImage()`、`app.ClipboardImagePNG()` | **写图片要平台层补** |
| 剪切板变化通知 | 无 | **平台层补** |
| 文件保存对话框 | 有（见 Viva `docs/system-integrations.md`，`NSSavePanel` / `IFileSaveDialog`），返回 `ErrCanceled` 表示取消 | 直接用，具体函数名以源码为准 |

> Viva 指南提醒：通用能力“应该进 Viva”。本项目作为应用，先在 `internal/platform` 里实现这些缺口，接口设计成以后能原样上游到 Viva 的样子（小、同步、返回 `error`，不支持时返回 `ErrUnsupported`）。

## 4. 运行时模型

### 4.1 启动

```go
func main() {
    cfg := config.Load()                       // 读 config.json，不存在写默认
    app.RunApplication(func(a *app.Application) error {
        platform.Init()                        // macOS: 设 Accessory 激活策略；Windows: 建消息窗口
        host := openHostWindow(a)              // 1×1 无边框窗口，打开后立刻 Hide，只为让应用常驻
        s := shell.New(a, host, cfg, deps...)
        s.AddTray()
        s.RegisterHotkeys()                    // 注册失败（被占用）→ 托盘提示，不退出
        s.StartClipboardWatch()
        return nil
    })
}
```

### 4.2 线程规则

1. **事件循环线程**（Viva 所谓 window thread / native event-loop thread）：所有 `OpenWindow`、窗口 `Paint`、输入回调、托盘菜单回调、`StatusItem` 方法都在这里。macOS 上是主线程。
2. 热键回调：macOS Carbon 热键在主线程派发；Windows 的 `WM_HOTKEY` 发到我们在事件循环线程上建的消息窗口。**两者都已经在事件循环线程上**，可以直接开窗口。
3. 后台 goroutine 只做：截图像素抓取（长截图）、PNG 编解码、拼接计算、历史文件读写。结果通过 `platform.PostMain(func())` 回到事件循环线程再改状态；或用窗口自己的 `Invalidator` + `OnWake`。
4. `platform.PostMain` 实现：macOS `dispatch_async(dispatch_get_main_queue(), …)`；Windows 对自建消息窗口 `PostMessageW(WM_APP+1)`，回调在 wndproc 里执行。用一个带锁的任务队列，消息只做“唤醒”。
5. Paint 只读状态，不改状态、不阻塞、不做 PNG 编码。状态变化放在输入回调或 `OnWake` 里。

### 4.3 截图流程（数据流）

```
热键 ──► shell.StartCapture(mode)
          │ 1. platform.Displays()            每个显示器：ID、逻辑 Bounds、Scale
          │ 2. platform.CaptureDisplay(id)    并发抓所有屏（goroutine + WaitGroup，≤150ms）
          │ 3. capture.Session{frames}        保存 *image.RGBA 与转好的 ui.Bitmap（预乘 BGRA）
          │ 4. 每个显示器 OpenWindow(Frameless, Origin=屏原点, Size=屏逻辑尺寸, Title="snaplite-overlay-<id>")
          │ 5. platform.RaiseOverlay(title, bounds)  置顶、覆盖菜单栏/任务栏、激活并取得键盘焦点
          ▼
     overlay 状态机：Idle → Selecting → Editing ─┬─► Done: raster.Compose → platform.SetClipboardImage → history.Add → 关闭所有遮罩
                                                 ├─► Save: 保存对话框 → 写 PNG → 同上
                                                 ├─► LongShot: 关闭遮罩 → longshot.Start(rect)
                                                 └─► Cancel: 关闭所有遮罩
```

同一时刻只允许一个截图/长截图会话；会话进行中再按热键忽略。

### 4.4 坐标系约定（重要）

| 坐标系 | 单位 | 原点 | 用在 |
| --- | --- | --- | --- |
| 屏幕逻辑坐标 | 逻辑像素（pt） | 主显示器左上角，y 向下 | Viva `Window.Frame`、`PointerEvent.ScreenX/Y`、`Config.Origin`、`platform.Display.Bounds` |
| 窗口坐标 | 逻辑像素 | 遮罩窗口左上角 | Paint、OnPointer |
| 图像坐标 | 物理像素 | 某张截图左上角 | 选区最终裁剪、标注存储、输出 |

- 每个遮罩窗口与一个显示器一一对应，窗口坐标 × `Display.Scale` = 该屏截图的图像坐标。`Scale` 取“截图像素宽 / 显示器逻辑宽”，不要假设 2.0。
- **标注统一存图像坐标**（物理像素），绘制到屏幕时除以 scale。这样遮罩、编辑器（可能缩放显示）、最终输出用同一份数据。
- macOS 的 CoreGraphics 全局坐标本身就是“主屏左上角、y 向下”，与 Viva 一致；NSScreen 的 frame 是左下角原点，平台层负责翻转。
- Windows 上进程须为 Per-Monitor V2 DPI 感知（Viva 已调用 `SetProcessDpiAwarenessContext`，平台层再确认一次即可）。Windows 的屏幕坐标是物理像素，平台层换算成逻辑像素后再交给上层（逻辑 = 物理 / 该屏 scale，scale = `GetDpiForMonitor` / 96）。务必在真机验证 Viva 的 `ScreenX/Y` 与此一致，若 Viva 在 Windows 上用的是物理像素，统一改成以 Viva 为准并记入偏差记录。

## 5. 错误处理与权限

- 平台层所有函数返回 `error`，用哨兵错误：`ErrUnsupported`、`ErrPermissionDenied`、`ErrHotkeyTaken`。上层用 `errors.Is` 判断。
- 截屏权限（macOS 屏幕录制）缺失：`CaptureDisplay` 返回 `ErrPermissionDenied` → 弹一个普通窗口说明“需要在 系统设置 › 隐私与安全性 › 屏幕录制 中允许简截”，按钮「打开系统设置」（`x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture`）。
- 辅助功能权限（macOS 自动滚动）缺失：长截图退化为手动模式，控制条上显示「开启自动滚动」链接（`?Privacy_Accessibility`）。
- 热键被占用：托盘 tooltip 和菜单首行（Disabled 项）提示“快捷键 ⌥F1 被占用，可在 config.json 修改”。
- 任何 panic 不能让托盘进程退出：shell 层在每个流程入口 `recover`，记录日志到数据目录 `snaplite.log`（只保留最近 1MB）。

## 6. 构建与打包

```bash
go build -o build/snaplite ./cmd/snaplite                      # 本机调试构建
GOOS=windows GOARCH=amd64 go build -o build/snaplite.exe ./cmd/snaplite   # 在 macOS 上交叉编译 Windows（纯 Go，无需 cgo）
go run github.com/vivaui/viva/cmd/viva@v0.2.1 package          # 生成 .app（macOS）/ NSIS 安装包（Windows）
```

`viva.toml`：

```toml
[app]
name = "简截"
id = "dev.snaplite.app"
version = "0.1.0"
executable = "snaplite"
package = "./cmd/snaplite"

[mac]
category = "public.app-category.utilities"
```

macOS 打包注意：Info.plist 需要 `LSUIElement = true`（不显示 Dock）、`NSScreenCaptureUsageDescription`。如果 `viva package` 不支持自定义这些键，就在 `viva package` 之后用 `plutil -insert` 补上，并写成 `scripts/package-mac.sh`。屏幕录制权限绑定代码签名，开发期用 ad-hoc 签名（`codesign -s -`），每次重新构建可能要重新授权——这是 macOS 行为，不是 bug。
